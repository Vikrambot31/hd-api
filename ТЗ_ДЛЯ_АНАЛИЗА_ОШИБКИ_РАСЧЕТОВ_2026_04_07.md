# ТЗ для анализа ошибки расчетов Human Design

Дата: 2026-04-07
Проект: web_calculator
Цель документа: передать другому ИИ полную картину проблемы с расчетами ворот и четкое техническое задание на исправление.

## 1. Кратко о проблеме

Пользователь сообщает, что для кейса:
- Дата: 20.05.1974
- Время: 15:25
- Город: Киев

в результатах отсутствуют 45-е ворота, хотя по пользовательскому эталону они должны присутствовать.

Важно: запуск сервера работает корректно и не должен изменяться. Исправлять только вычисления.

## 2. Ограничения задачи

1. Не трогать запуск и инфраструктуру:
- start_local_server.cmd
- start_local_server.ps1
- любые настройки старта/деплоя

2. Работать только с расчетной логикой:
- hd_api.py
- fullhd_lookup.json и связанные генераторы/импортеры
- сопутствующие тесты/валидация

3. Эталонные источники для сверки:
- папка FullHD - etalon
- в первую очередь файлы с листом FullHD

## 3. Что уже обнаружено

### 3.1 Противоречие в контрольных точках

В проекте есть конфликтующие версии контрольных точек:
- Версия A (старые документы/валидатор):
  - 24.4 -> Gate 44
  - 11.5 -> Gate 45
- Версия B (часть последних правок и текущие данные FullHD в xlsx/json):
  - 24.4 -> Gate 42
  - 11.5 -> Gate 21

Это ключевой источник путаницы. Нужно определить единственный источник истины по эталонам пользователя.

### 3.2 Текущее состояние lookup

Текущий fullhd_lookup.json имеет 13824 записей (дискретизированная таблица) и в текущем виде показывает:
- 11.5 -> Gate 21
- 24.4 -> Gate 42

### 3.3 Найденный расчетный регресс в API

В hd_api.py изначально отсутствовал расчет Южного Узла (South Node, ☋), хотя Северный Узел есть.

Это важно, потому что в кейсе 20.05.1974 15:25 Киев 45-е ворота приходят именно через противоположную точку к Северному Узлу.

Была добавлена логика:
- Южный Узел = Северный Узел + 180°
- Добавление Южного Узла в personality_planets и design_planets
- Добавление его gate в personality_gates/design_gates

Но пользователь подтверждает, что задача в его понимании пока не закрыта, значит нужен независимый полный пересмотр.

## 4. Что требуется от другого ИИ (ТЗ)

### 4.1 Главная цель

Найти и устранить корневую причину расхождения расчетов ворот с эталоном пользователя для кейса 20.05.1974 15:25 Киев и связанных кейсов.

### 4.2 Обязательные шаги анализа

1. Зафиксировать базовый reproduction:
- Запрос к API /api/calc с параметрами 1974-05-20 15:25, Киев
- Явно проверить набор all_gates, personality_gates, design_gates
- Проверить наличие Gate 45

2. Верифицировать вычисление времени:
- Проверить используемый tz_offset
- Проверить исторический пояс Киева на дату 20.05.1974 (включая DST)
- Проверить, не возникает ли сдвиг 1 час, меняющий ворота

3. Верифицировать расчет астроданных:
- Какие тела реально считаются (Sun, Moon, планеты, N.Node, Chiron)
- Какие тела обязаны участвовать в определении ворот по пользовательскому эталону
- Отдельно проверить Earth и South Node

4. Верифицировать lookup-мэппинг:
- Сравнить fullhd_lookup.json с исходными таблицами из FullHD - etalon
- Проверить корректность импорта из Excel (колонки, диапазоны, сортировка, модуль 360)
- Проверить контрольные точки, но не принимать их безусловно: сначала вывести из эталона

5. Сверить итог с эталоном пользователя:
- Для тест-кейса получить таблицу planet -> longitude -> gate.line
- Показать расхождения построчно с эталоном

### 4.3 Требуемые артефакты результата

1. Патч кода с минимальными изменениями.
2. Отдельный отчет:
- root cause
- какие файлы изменены
- почему теперь корректно

3. Набор регрессионных тест-кейсов (минимум 5):
- включая 20.05.1974 15:25 Киев
- и еще 4 кейса из эталона (если доступны)

4. Чек-лист приемки, где явно подтверждено:
- Gate 45 присутствует там, где должен
- расчет не ломает другие ворота/каналы/центры
- запуск сервера не изменялся

## 5. Критерии приемки (Definition of Done)

Считать задачу решенной только если выполнено все:

1. Для кейса 20.05.1974 15:25 Киев результат совпадает с эталоном пользователя по воротам.
2. Подтверждено, из какого астропараметра появляется Gate 45 (планета/узел/земля).
3. Устранено противоречие контрольных точек (11.5/24.4) и выбран единый источник истины.
4. Добавлены и пройдены регрессионные проверки.
5. Не изменены скрипты запуска и серверная инфраструктура.
